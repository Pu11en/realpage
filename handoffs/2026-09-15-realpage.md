## Decisions

- **Frozen numbers, never auto-refreshed.** The page shows a date; no live refresh loop.
- **Final live run = security headers + agent only.** No website-flow tests, no code scan
  (Drew: "just do the security headers and agent").
- **Off-topic pass rate dropped as a metric** (Drew doesn't care about it); the rewritten test set
  has no off-topic category.
- **Test set rewritten around real sales-rep questions** (40: find-leads 8, research 8,
  who-to-call 6, competitors 6, industry 6, trick 6) because the old set asked things no rep would.
- **Every lead must be actionable**: phone/contact or link, else a one-tap "🔍 Find contact".
  No auto deep dive for every lead (slow, and it would burn the free plan's 3 deep dives/week).
- **Phones come from permit records**, so they are the developer's/owner's office; label them
  "permit contact". Never invent one; reformat rather than delete.
- **Agent rules loosened deliberately** (Drew picked the widest option): links only when a fact
  came from the web or is a building claim; general knowledge allowed but labelled; touchy topics
  (lawsuits) neutral facts only; RealPage overviews may run to ~120 words. Hard rules kept:
  no invented contacts or links, no software claim without proof, read-only, no personal data,
  no legal/financial advice.
- **Public repo content:** the tool plus CraneSignal's frozen results as a worked example; strip
  lead data, answer-key details, Drew's grading notes and local paths. **Nothing goes to GitHub
  until Drew says so** — the shipcheck repo does not exist yet and the eval folder has no remote.
- **Wording on the page must be honest**: say the real count asked (40 of a 100-question set), say
  a person graded the failures, show open issues rather than hiding them.
- **Parallel work is fine** as long as sessions touch different folders; the realpage.com library
  thread was told to go ahead — all chatbot rule changes are already in `main`.
